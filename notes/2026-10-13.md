# 2026-10-13 — 출퇴근 QR 1단계

## 구조
- 카운터 고정 QR `/clock?k=비밀값` → 첫 스캔은 새 직원 등록(이름만), 이후 쿠키(`sb_device`, 1년)로 자동 인식
- 출퇴근은 버튼: QR을 찍으면 3분 입장권(`sb_ticket`) 발급 + 주소에서 k 제거 → [출근하기]/[퇴근하기] 1회 → 입장권 소멸
- 링크·열어 둔 탭·새로고침은 현황(이번 달 기록)만, 버튼 없음. 집에서 누르기 불가
- 어제 퇴근 누락 → 안내 문구 + 오늘 출근 가능 (v2 SQL 필요)
- 폰 교체·기존 직원 첫 연결: 점장이 `/staff` 직원·폰 탭에서 [연결 QR] (10분, 1회용) → `/clock/link?t=토큰`
- PIN 없음. 같은 이름 새 등록은 차단. 등록도 QR 입장권 있을 때만

## 근무일지 엑셀 (`/api/attendance/export?year=&month=`)
- 기존 P.T. 근무일지 구조: 평일 블록 / 주일 블록 / M월분 총 인건비(세전)
- 대상: 직책 알바생(part_time)만. 점장·매니저는 수기 항목(payroll_items)으로
- 같은 날 여러 번 근무 → 첫 출근~마지막 퇴근, 시간 합산
- 퇴근 누락은 근무시간 0 + "누락" 표시, 상단 경고
- 계산값으로 기록 (수식 아님)

## 직원용 주소 분리 (`proxy.ts`)
- `NEXT_PUBLIC_CLOCK_ORIGIN` 주소로 오면 `/clock`, `/api/clock/*`만 허용 (`/`는 `/clock`으로), 나머지 404
- 카운터 QR·연결 QR이 이 주소로 만들어짐 → 직원 폰에 관리용 주소가 남지 않음
- 로컬 확인: 프로덕션 빌드에서 직원용 주소 → 출퇴근만, `/staff` 404 / 관리용 주소 → 정상
- 개발 서버(`npm run dev`)에서 127.0.0.1을 직원용으로 쓰면 Next 개발 리소스 차단으로 화면이 멈춤 (개발 전용 현상)
